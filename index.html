Problem and parameters

Changed parameters take effect when you apply and reset; past iterations are never rewritten. Higher w favors exploration, lower w favors local search, c1 weights each particle’s own memory, c2 weights the swarm’s best. No setting guarantees convergence.

PSO in one page
Each particle i has a position x and a velocity v. It remembers its personal best pBest, and the swarm shares one global best gBest.

v(t+1) = w·v(t) + c1·r1·(pBest − x) + c2·r2·(gBest − x)
x(t+1) = x(t) + v(t+1)

w is inertia, c1 is the cognitive (own memory) pull, c2 is the social (swarm) pull, and r1, r2 are fresh random numbers in [0,1] for every dimension.

Pseudocode
1. Scatter N particles in the search space with random velocities.
2. Evaluate every particle; set pBest = position; set gBest to the best.
3. Repeat until the iteration limit: for each particle, compute the new velocity, clamp it to ±vmax, move, clamp the position to the bounds (velocity in that dimension is set to 0), evaluate, update pBest if better. Then update gBest from the pBests.

This tool uses synchronous gBest: all particles in an iteration see the same gBest from the end of the previous iteration.


Notes
Cost: O(N·T) function evaluations; memory O(N·d).
Strengths: few parameters, no gradients, easy to implement.
Weaknesses: can stall in local minima (try Rastrigin), parameter sensitive, no convergence guarantee.
Versus Genetic Algorithm: PSO keeps every individual and steers it with memory; a GA selects, crosses over and mutates.
Versus Artificial Bee Colony: ABC uses employed, onlooker and scout bees with greedy neighbour search; PSO uses velocity with momentum.
Variants: constriction-factor PSO, linearly decreasing inertia, local-best (ring topology), adaptive PSO.
Applications: neural-network training, tuning controllers, scheduling, feature selection.
